# Compare view

**Decided:** 2026-10-16

**Choice:** Compare, a chip at the top left of the GUI's preview, swipes the current drawing against the previous run's drawing or against the source image. They share the page and the zoom. A vertical divider runs across the preview: left of it is the comparison, right of it the current drawing, and a slider along the preview's foot moves the divider with the mouse or the keyboard. The previous drawing is the result the latest one replaced. It is kept in the page only, so a reload forgets it and nothing reaches the engine, the preset or the undo history. The source shows as the tone map at full strength, the grey the pen would ink, rather than the 30 percent the Source overlay uses. The comparison is hidden while a run draws. This settles the compare view proposed for after 0.1 in §12, question 8.

**Reason:** A settings change is judged by where it moved the marks, and two drawings side by side at half the size each hide the small moves that matter, such as a denser hatch in one shadow. A swipe keeps both at full size, aligned to the same paper millimetre, so the eye compares the same spot. The previous run is the comparison asked for most after a change, and the source answers whether the drawing follows the picture. Keeping only one earlier drawing, in memory, costs one result's arrays and needs no storage, history or engine change. A run in progress draws frames, so a comparison over it would compare a half-made drawing. The chip sits on the preview rather than in the toolbar, because the toolbar was sized to keep its labels in one row on a desktop window, and a third view chip there would have cost them.
