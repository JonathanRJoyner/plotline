# Narrow toolbar

**Decided:** 2026-10-16

**Choice:** the toolbar sheds labels as the preview column narrows, measured with a container query on that column. Below 1340 px, Source, Travel, Fit page, Export SVG, Settings and Tour show their icons alone, and so does Focus. Below 910 px every button but Run does. From 340 px to 660 px the toolbar is a grid of two even rows: open, run and undo above, view, fit and the app buttons below. A shed label stays in the button as visually hidden text, so the button keeps its accessible name, and a title shows the name on hover.

**Reason:** the owner disliked how the toolbar stacked on smaller screens. With every label it needed 1194 px, so a 1730 px window wrapped it and left Export SVG, Settings, Tour and the theme button alone on a second row, pushed to the right. The two tiers needed 829 px and 596 px, so the toolbar stays on one row from a 620 px preview column up, which covers a 1280 px laptop. A wrapped flex row cannot be balanced in CSS, so the narrowest widths use a fixed two-row grid instead. Below 340 px that grid would overflow, so the toolbar wraps there as before. The thresholds leave about 5 % for fonts wider than the Windows system font the widths were measured in.

**Amended 2026-10-16** under the [focus points decision](2026-10-16-focus-points.md): the Focus chip joins the Fit page group, which needs 87 px more with every label and 37 px more as an icon, measured as the widths of the toolbar's groups and gaps (1281 px with every label, 866 px with the first tier shed, 632 px with all but Run), so the thresholds moved from 1240, 880 and 620 px to 1340, 910 and 660 px, the same 4 to 6 % above the need. In the two-row grid the zoom readout no longer holds 3.5 em, so the chip still fits from 340 px, as the browser flow at 375 px checks.
