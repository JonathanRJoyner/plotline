# Share link

**Decided:** 2026-10-17

**Choice:** The GUI's Copy link button copies `location.origin + location.pathname + "#p=" + encoded`, where `encoded` is the same preset that Save preset writes, as compact JSON, compressed with the browser's `CompressionStream("deflate-raw")` (RFC 1951) and written as base64url without padding (RFC 4648 section 5). The setup goes in the URL fragment, never the query string. On load, a fragment that starts with `#p=` is decoded with `DecompressionStream` and loaded through the same function as Load preset, so warnings for dropped settings show the same way; the fragment is then removed with `history.replaceState`, so a reload does not apply it over later edits. The link's setup is loaded after the remembered one, so it wins and is one step in the undo history, which goes back to the remembered setup. The link never carries a machine: it is written with `machine` null, and opening one keeps the machine the browser already had. A fragment that fails to decode (bad characters, bad deflate data, or more than 1 MiB of text) shows a plain error under Presets and leaves the remembered setup alone. When the clipboard refuses, the link is shown in a text field to copy by hand. No dependency was added.

**Reason:** A preset holds no image, so it fits in a link and a setup can be shared in a forum post without attaching a file. A fragment is not sent to a server, so the hosted page sees nothing of it and the page stays fully static. The browser's own compression covers what a short link needs, so no library has to be vetted for its licence or counted against the wasm and bundle size. Applying the link once and clearing it keeps the address bar from re-applying an old setup on reload. The 1 MiB cap on decoded text stops a small link from inflating into memory-sized text; a preset is a few kilobytes. For the default setup (the first style, no image) the fragment is 479 characters, measured in Chromium on 2026-10-17.
