# Pen use Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let every style draw with several pens: a shared Pen use stage turns the tone map into one map per pen, and the runner runs the rest of the style once per pen.

**Architecture:** A new kind, `Tones`, marks a split. `Style::new` resolves the stages after a split per lane: `Tone` resolves to the lane's map and `Pens` to a one-pen list. `Run` runs the stages before the split once, then the rest lane by lane. Lane tone maps are keyed by their content, so caching stays per stage and per pen. The split stage has three modes; colour mode uses a Demichel and Neugebauer coverage model solved by coordinate descent into a lookup table. Line styles read their lane to spread their angles, start or grid across pens. Hosts pass the frame's pen through, and the GUI puts the setting in the Pens panel.

**Tech Stack:** Rust (plotline-core, PyO3, wasm-bindgen), Python 3.11+ (uv, pytest), TypeScript with Preact and vitest.

**Spec:** [docs/superpowers/specs/2026-10-12-pen-use-design.md](../specs/2026-10-12-pen-use-design.md)

2. **Two pens of the same colour in `by_colour`.** Expect no NaN: the first pen in the sweep order takes the ink and the other gets 0. Test in Task 4.

Rules for `next_frame`, which otherwise keeps its structure:
- **Which stage is next.** Without a split, or while `done.len() <= split`, it is `done.len()` with no lane, as now. After that it is stage `split + 1 + lanes[l].done.len()` of the first lane `l` whose `done` is shorter than `stages.len() - split - 1`. When no lane is left, the run is finished.
- **Entering the lanes.** When the split stage's artifact lands in `done`, whether computed or cached, build `lanes` from its maps.

- **Inputs in lane `l`.**
  - `Source::Stage(j)` with `j <= split` reads `done[j]`; with `j > split` it reads `lanes[l].done[j - split - 1]`.
  - `Source::Lane(Tone)` and `Source::Lane(Pens)` read the lane's entries.
  - The key map gains `"lane" -> format!("{l}/{n}")`.
  - The stage starts with `RunContext::new(..).in_lane(Lane { index: l, count: n })`.
- **Frames.** Set `frame.pen` to the lane index (0 outside lanes) wherever `frame.stage` is set, including the `"cached"` frame.
- **The drawing.** `drawing()` builds one layer per lane from the lane's last artifact. A non-`Paths` artifact is a bug: `panic!` as today. The tone map still comes from the stages before the split.

### Task 4: By colour

**Files:**
- Modify: `crates/core/src/stages/split.rs`, `crates/core/src/stages/tone.rs` (make `crop_to_aspect` and `resize` `pub(crate)`), `crates/core/src/preview.rs` (make `rgb` `pub(crate)`)

**Interfaces:**
- Consumes: Task 3's `SplitStage` and `run_split` helper.
- Produces (all `pub(crate)` in `split.rs`):
  - `const LAMBDA: f64 = 1e-3; const SWEEPS: usize = 64; const LEVELS: usize = 17;`
  - `fn rescale(c: [f32; 3], t: f32) -> [f64; 3]`:
    - `u = 1 - (0.299 r + 0.587 g + 0.114 b)` in f32, the same expression as `Image::luminance`;
    - if `u < 1e-6`, return the grey `1 - t`;
    - otherwise each channel is `1 - min(1, (1 - c_k) * t / u)`.
  - `fn absorption(pen: &Pen) -> [f64; 3]`: `1 - byte / 255` per channel of `preview::rgb(&pen.color)`.
  - `fn sweep_order(absorb: &[[f64; 3]]) -> Vec<usize>`: pens by total absorption, largest first; ties keep list order (a stable sort).
  - `fn sweep(a: &mut [f64], target: [f64; 3], absorb: &[[f64; 3]], order: &[usize])`: one exact coordinate-descent pass.
  - `fn energy(a: &[f64], target: [f64; 3], absorb: &[[f64; 3]]) -> f64`: `E(a)` from spec §3.3.
  - `fn coverages(target: [f64; 3], absorb: &[[f64; 3]]) -> Vec<f64>`: zeros, then `SWEEPS` sweeps in `sweep_order`.
  - `struct Table`, with `Table::new(absorb: &[[f64; 3]]) -> Table`, solving `coverages` at the `LEVELS`³ colours `j / 16`, and `Table::lookup(&self, c: [f64; 3], out: &mut [f64])`, interpolating trilinearly with each axis clamped to [0, 1].

`sweep` is the one body the spec's formula does not fix as code:

```rust
for &i in order {
    let (mut num, mut den) = (0.0, 0.0);
    for c in 0..3 {
        let q: f64 = (0..a.len()).filter(|&j| j != i).map(|j| 1.0 - a[j] * absorb[j][c]).product();
        let g = absorb[i][c] * q;
        num += g * (q - target[c]);
        den += g * g;
    }
    a[i] = if den > 0.0 { ((num - LAMBDA / 2.0) / den).clamp(0.0, 1.0) } else { 0.0 };
}
```

Why darkest first: from zero, a sweep in list order lets cyan, magenta and yellow claim a black before the black pen is visited. That is a coordinate-wise minimum the descent cannot leave. Visiting the darkest pen first gives it the shared darkness, and the penalty then keeps the colour pens out of the greys. Say this in a comment and in the module doc.

### Task 5: Spread each pen's lines and dots

**Files:**
- Modify: `crates/core/src/stages/{hatch,waves,spiral,grid}.rs`, `crates/core/src/test_util.rs`

**Interfaces:**
- Consumes: `RunContext::lane()` from Task 1.
- Produces: `test_util::run_tone_stage_in_lane(stage, tone, patch, lane: Lane) -> (Vec<Frame>, Arc<Paths>)`. `run_tone_stage` calls it with `Lane::SINGLE`. Grid's local `run_stage` test helper gains a `lane: Lane` argument, and its existing calls pass `Lane::SINGLE`.

Rules, with `Lane { index: i, count: n }` read from `ctx.lane()` in `start` (spec §5):
- **hatch.** Level `k` is drawn at `s.angle_deg + 180.0 * (k * n + i) / (levels * n)`, all as f64.
- **waves.** Lines run at `s.angle_deg + 180.0 * i / n`, for both `scanlines` and `direction`.
- **spiral.** Every `math::sin(theta)` and `math::cos(theta)` becomes `math::sin(theta + phi)` and `math::cos(theta + phi)`, with `phi = 2.0 * PI * i / n`.
- **grid.** With `d = spacing * i / n`, the grid's origin is `[x0 + d, y0 + d]`, `cols = ((w - d) / spacing + 1e-9).floor()` and `rows` likewise.

With `i = 0` every expression reduces exactly to today's (adding `+ 0.0`, or multiplying and dividing by `1.0`), so one lane is bit-identical.
