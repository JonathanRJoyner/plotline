# plotline GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the browser GUI: the WebAssembly engine in a Web Worker, a live Canvas 2D preview, a settings form generated from the style schema, page, pen, speed, preset and export panels, the bundle built into the Python package for `plotline gui`, and CI for it.

**Architecture:** The worker owns the one wasm `Session` and answers `{id, method, args}` commands with the whole state; a driver loop pulls frames from a `Run`, posts them as transferred typed arrays at most 30 times a second, and yields to the event loop every 50 ms so cancel gets in. The page is Preact with hooks: a thin `Engine` client over the worker, pure modules for path iteration, schema-to-controls and view math, and components for the preview, the settings form and the side panels.

**Tech Stack:** Rust (wasm-bindgen additions), TypeScript ~5.9, Vite ^7, Preact ^10.27, `@preact/preset-vite` ^2.10, vitest ^4, `@types/node` ^22, Node 22 in CI, wasm-pack.

**Spec:** `docs/superpowers/specs/2026-10-12-gui-design.md`

## Global Constraints

- No Python or Rust dependency is added. The only runtime JavaScript dependency is preact (MIT). vite, typescript, `@preact/preset-vite`, vitest and `@types/node` are dev dependencies.
- The bundle is written to `src/plotline/web`, which `.gitignore` lists; `web/pkg` (the wasm-pack output) is already ignored. Neither is ever committed.
- `vite build` uses `base: "./"`, so the bundle works at a server root and under a path.
- Every wasm handle (`Run`, `FrameHandle`, `DrawingHandle`) is freed with `.free()` once its data has been copied out.
- No algorithm code in the GUI: the worker calls the session, nothing else computes geometry.
- No other products are named in code, docs or commit messages. No third-party images; sample images come from the engine's synthetic generators.
- Before every commit the verification set passes from the repo root: `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace` when Rust changed; `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`, `uv run pytest -q` when Python changed; `npm run check` in `web/` when the web app changed.
- Commit messages are plain imperative sentences like the existing history and end with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`, passed as a second `-m`.
- The versions above are deliberate: newer majors of Preact, Vite and TypeScript exist, but these are the ones whose APIs are known. If `npm install` refuses a range, take the nearest version that installs and note it in the commit message.

## Review Focus

1. Bytes that are not a PNG or JPEG (a text file, a truncated image) go to `setImageBytes`: the reply is `ok: false` with the engine's message, the state is unchanged, and no run starts. Test in Task 5.
2. A number typed over a setting's maximum (`resolution` 10, below its minimum of 64): the engine refuses it, the reply carries the message, and the settings in the state are unchanged. Test in Task 5.
3. A preset file with the wrong `format` or a version above 1: `loadPreset` replies `ok: false` and the style, canvas, pens and settings are unchanged. Test in Task 5.
4. A pen with width 0 or a colour that is not `#rrggbb`: `setPens` is refused with the message and the pens are unchanged. Test in Task 5.
5. A second run started while a slow stage is running: the first run ends with `cancelled`, exactly one `end` event per run, and the page shows the newer run only. Test in Task 4.

### Task 3: Pure modules: paths and schema controls

**Files:**
- Create: `web/src/paths.ts`, `web/src/schema.ts`
- Test: `web/src/paths.test.ts`, `web/src/schema.test.ts`

**Interfaces:**
- Produces, in `paths.ts`: `pathCount(offsets: Uint32Array): number`, which is `max(0, offsets.length - 1)`; `eachPath(coords: Float64Array, offsets: Uint32Array, fn: (start: number, end: number) => void): void`, calling `fn` once per path with vertex indexes `start` (inclusive) and `end` (exclusive) into the x, y pairs of `coords`, so vertex `v` is at `coords[2 * v]`, `coords[2 * v + 1]`.
- Produces, in `schema.ts`: `type Control` as the union below and `controlsFor(schema: Record<string, unknown>): Control[]`, in the schema's property order.

```ts
type Base = { key: string; label: string; help: string; advanced: boolean };
export type Control =
  | (Base & { kind: "checkbox"; default: boolean })
  | (Base & { kind: "slider"; min: number; max: number; step: number; integer: boolean; unit: string | null; default: number })
  | (Base & { kind: "number"; integer: boolean; unit: string | null; default: number | null })
  | (Base & { kind: "select"; options: { value: string; label: string; title: string | null }[]; default: string | null })
  | (Base & { kind: "text"; default: string | null });
```

Rules, from spec §6.3: `label` is `x-label` or the key with underscores as spaces; `help` is `description` or `""`; `advanced` is `x-advanced === true`; `unit` is `x-unit` or null. A `boolean` is a checkbox. An `integer` or `number` with both `minimum` and `maximum` is a slider whose step is `x-step`, else 1 for an integer, else `(max - min) / 100`. Other numbers are a number control. A property is a select when it has `enum`, or when its `$ref` (also one found in a one-element `allOf`) points into the schema's `$defs` or `definitions` and that definition has `enum` or a `oneOf` of `const` entries; the option label is the value and the title its `description` or null. Anything else is text. `default` is the schema's `default` or null.

### Task 4: The driver

**Files:**
- Create: `web/src/driver.ts`, `web/src/events.ts`
- Test: `web/src/driver.test.ts`

**Interfaces:**
- Consumes: `Session`, `Run`, `FrameHandle`, `DrawingHandle` from `../pkg/plotline_wasm.js`, with Task 1's additions.
- Produces, in `events.ts`, the event types of spec §5:

```ts
export type Pen = { name: string; width_mm: number; color: string };
export type Canvas = { width_mm: number; height_mm: number; margin_mm: number; fit: "fit" | "fill" };
export type Tone = { x: number; y: number; w: number; h: number; width_px: number; height_px: number; ink: Uint8Array };
export type Layer = { pen: Pen; coords: Float64Array; offsets: Uint32Array };
export type Stats = { path_count: number; pen_down_mm: number; pen_up_mm: number; estimated_seconds: number };
export type RunEvent = { type: "run"; id: number };
export type FrameEvent = { type: "frame"; id: number; stage: string; progress: number; label: string; points?: Float64Array; coords?: Float64Array; offsets?: Uint32Array };
export type ResultEvent = { type: "result"; id: number; canvas: Canvas; layers: Layer[]; tone: Tone | null };
export type EndEvent = { type: "end"; id: number; state: "done" | "cancelled" | "error"; error: string | null; stats: Stats | null };
export type Event = RunEvent | FrameEvent | ResultEvent | EndEvent;
```

- Produces, in `driver.ts`: `type Post = (event: Event, transfer: Transferable[]) => void`; `macrotask(): Promise<void>` (a `MessageChannel` round trip, the channel made once and its port unreffed when `unref` exists, so Node exits); and

```ts
export async function drive(session: Session, run: Run, id: number, post: Post,
  opts: { frameMs?: number; yieldMs?: number; now?: () => number; yieldFn?: () => Promise<void> } = {}): Promise<void>
```

which posts `run`, then loops over `run.nextFrame()` as spec §5 says: geometry is read and the frame posted when at least `frameMs` (default 33) has passed since the last post (which starts at `-Infinity`, so a run's first frame always posts) or `progress >= 1`; the handle is freed either way; after every `yieldMs` (default 50) of work it awaits `yieldFn` (default `macrotask`). When `nextFrame()` is `undefined`: if `run.state()` is `"done"`, it reads `session.drawing()`, posts `result` with one layer per `layerCount()` (its `layerPen`, `layerCoords`, `layerOffsets`) and the tone map from `toneRect`/`toneInk`, frees the handle; then posts `end` with `run.state()`, `run.error() ?? null` and the parsed `session.stats() ?? null`; then frees the run. The transfer list of a frame or result holds every typed array's `buffer`.

### Task 5: The worker protocol and the main-thread client

**Files:**
- Create: `web/src/protocol.ts`, `web/src/worker.ts`, `web/src/engine.ts`
- Test: `web/src/protocol.test.ts`

**Interfaces:**
- Consumes: `drive` and `Event` from Task 4; `listStyles`, `describe`, `Session` from the module.
- Produces, in `protocol.ts`, with `Canvas`, `Pen`, `Stats` and `Event` imported from `./events`:

```ts
export type Speeds = { draw_mm_s: number; travel_mm_s: number; pen_lift_s: number };
export type State = { image: boolean; style: string; canvas: Canvas; pens: Pen[]; settings: Record<string, Record<string, unknown>>; speeds: Speeds; run: { id: number; state: string; error: string | null }; stats: Stats | null };
export type Command = { id: number; method: string; args: unknown[] };
export type Reply = { id: number; ok: true; state: State; value?: unknown } | { id: number; ok: false; error: string };
export class Protocol {
  constructor(session: Session, post: (msg: Reply | Event, transfer?: Transferable[]) => void);
  handle(cmd: Command): void;
}
```

Methods, as spec §5 plus two for tests and the sample button: `listStyles()` (value: the parsed list), `describe(name)` (value: the parsed schema), `setImageBytes(bytes: Uint8Array)`, `setImage(width, height, rgb: Float32Array)`, `sample()` (sets a 400 by 300 `syntheticGradient`), `setCanvas(canvas)`, `setPens(pens)`, `setStyle(name)`, `update(stage, values)`, `setSpeeds(speeds)`, `run()`, `cancel()`, `preset()` (value: the parsed preset), `loadPreset(preset)` (value: the warnings array), `svg()` and `json()` (value: the text). JSON arguments are stringified for the session and its JSON results parsed. An unknown method or a thrown error replies `ok: false` with `String(error.message ?? error)`. `setImageBytes`, `setImage`, `sample`, `setCanvas`, `setPens`, `setStyle`, `update` and `loadPreset` start a run after they succeed when an image is set; `run()` always starts one; `cancel()` calls `cancel()` on the current `Run` when there is one. Starting a run increments the run counter, calls `session.start()`, keeps the `Run` and calls `drive` without awaiting it. The state is built from `session.preset()` (style, canvas, pens, settings), `session.speeds()`, the counter with `session.state()` and `session.error() ?? null`, and `session.stats()` parsed or null; `image` is a flag the protocol sets when an image command succeeds.

- Produces, in `worker.ts`: the module entry that awaits `init()`, makes `new Protocol(new Session(), (msg, transfer) => self.postMessage(msg, { transfer: transfer ?? [] }))`, then sets `self.onmessage` to pass `event.data` to `handle`. Commands that arrive before `init` resolves are queued and handled after it.

- Produces, in `engine.ts`:

```ts
export class Engine {
  constructor(worker: Worker);
  onEvent: (event: Event) => void;
  call<T = undefined>(method: string, args?: unknown[], transfer?: Transferable[]): Promise<{ state: State; value: T }>;
}
```

`call` posts `{id, method, args}` with a fresh id and resolves on the matching reply, or rejects with `new Error(error)`; messages with a `type` go to `onEvent`.
