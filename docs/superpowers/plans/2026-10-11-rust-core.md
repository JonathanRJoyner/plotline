# plotline Rust Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Python engine with one Rust crate that compiles to a native Python extension and to WebAssembly, keeping the design, formats and Python surface of spec 1.

**Architecture:** `crates/core` is a pure library (no I/O, no threads) holding types, settings, stages, styles, runner, cache, session, export, stats, preview, presets and image decoding. `crates/py` wraps it with PyO3 for the `plotline` Python package, which keeps only threads, files, callbacks and the CLI. `crates/wasm` wraps the same session for the browser. Stages are step functions pulled by the host, so a Web Worker can cancel between steps.

**Tech Stack:** Rust stable, serde, serde_json, schemars 1, rand 0.9 with rand_pcg, libm, image 0.25, tiny-skia 0.11, blake3, thiserror; PyO3 with rust-numpy and maturin; wasm-bindgen with wasm-pack; Python 3.11+, uv, numpy, click, pytest, ruff, mypy; cargo-deny.

**Spec:** [docs/superpowers/specs/2026-10-11-rust-core-design.md](../specs/2026-10-11-rust-core-design.md). Spec 1, whose formulas and formats carry over, is [docs/superpowers/specs/2026-10-11-core-engine-design.md](../specs/2026-10-11-core-engine-design.md). The Python engine on `main` is the reference implementation; its tests hold the pinned values reused below.

Three details differ from the spec as written and were amended in it alongside this plan: the tone stage resamples the way the Python engine does (block average, then bilinear at pixel centres) instead of the `image` crate's triangle filter, so its tests carry over; the ordering stage breaks exact distance ties by lowest endpoint index, which the kd-tree did not do reproducibly, so path order may differ from the Python engine only on exact ties; the float-method rule is checked by a source-scan test instead of a clippy configuration. The synthetic images and a hidden `_slow` test style are always compiled, not feature-gated, so Python and Node tests can use them from release builds.

## Global Constraints

- Every dependency is MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, CC0-1.0 or Unicode-3.0 (or an OR-combination of those). `cargo deny check licenses` and `scripts/check_licenses.py` both pass.
- Rust stable, edition 2021, toolchain pinned in `rust-toolchain.toml`. `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` pass.
- Python 3.11 or newer; wheels are `abi3-py311`.
- Coordinates are page millimetres, origin top-left, y down. Tone values are `f32`, coordinates `f64`.
- Transcendental functions go through `crates/core/src/math.rs` (libm). `mul_add` is never used. No `HashMap` iteration order reaches output.
- Every algorithm module's doc comment cites its published source. No other product is named anywhere.
- No third-party images. Test images come from `synthetic.rs`.
- Public, copy-ready repository: no personal paths, no credentials.
- Commit after every task with a message in full sentences; the subject names the change, the body says why when the why is not obvious.

## Review Focus

1. A photo with an EXIF rotation tag: the drawing must be upright, not sideways. Test in Task 13.
2. A PNG with transparency: transparent pixels must become white (paper), not black. Test in Task 13.
3. `update` with a value of the wrong JSON type, such as `"resolution": "500"` from a hand-edited preset: a clear error naming the stage and key, no panic. Test in Task 3.
4. A run started while another run is in progress: the first run ends `Cancelled`, the second completes, and the cache is used by only one at a time. Test in Task 15.
5. An image whose tone map is one pixel on the short side (extreme aspect ratio): no division by zero, the grid still places points. Test in Task 8 (tone) and Task 9 (grid).

### Task 3: Settings schema and validation

**Files:**
- Create: `crates/core/src/settings.rs`
- Modify: `crates/core/src/lib.rs`

**Interfaces:**
- Produces:
  - `pub fn schema_for<S: JsonSchema>() -> serde_json::Value` returning `schemars::schema_for!(S)` as a Value with the `$schema` key removed.
  - `pub fn defaults_for<S: Serialize + Default>() -> serde_json::Value`.
  - `pub fn validate<S: DeserializeOwned>(stage: &str, schema: &Value, value: &Value) -> Result<S, SettingsError>`: `value` must be a JSON object; every key must be in `schema.properties` (else `SettingsError::UnknownKey { stage, key }`); for a number property with `minimum`/`maximum`, the value must lie inside (else `SettingsError::OutOfRange { stage, key, value, min, max }`); for a property with `enum`, the value must be one of them (else `SettingsError::NotAChoice { stage, key, value, choices }`); finally `serde_json::from_value` (else `SettingsError::Invalid { stage, key_or_empty, message }`). `Display` for every variant starts with `"stage {stage!r}, setting {key!r}: "`, the `Invalid` variant without a key starts with `"stage {stage!r}: "`.
  - `pub fn merge(current: &Value, patch: &Value) -> Value`: shallow object merge, `patch` wins.
- Convention for every settings struct: `#[derive(Clone, Debug, PartialEq, Serialize, Deserialize, JsonSchema)]`, `#[serde(default, deny_unknown_fields)]`, an `impl Default` with the spec's defaults, doc comments as help text, `#[schemars(range(min = .., max = ..))]` for bounds, `#[schemars(extend("x-unit" = "mm"))]`, `"x-step"`, `"x-label"`, `"x-advanced" = true` as needed.

- Behaviour of `next_frame`, per spec §8: on first call set `shared.state = Running`. For the current stage: if no `StageRun` is active, compute the key; if cached, record the artifact and return `Frame { progress: 1.0, label: "cached" }` and advance; else `start` the stage (settings for the stage are `settings[name]` merged over `stage.defaults()`), on `Err` finish with `Error`. After the last stage, build the `Drawing` (layers from a `Layers` artifact, else one `Layer` with `pens[0]` and the `Paths`; `tone` from the last stage that provides `Tone`), set `shared.drawing` and `state = Done`, return `None`. A cancelled or failed run leaves `shared.drawing` unchanged, stores nothing for the stage in progress, and keeps earlier stages cached. The cache mutex is held only during `get` and `put`.
